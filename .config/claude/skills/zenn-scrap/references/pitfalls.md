# zenn スクラップの DOM と過去の事故

スクリプトが壊れたとき (`no candidate` / `editor not open` など) に DOM を調べ直すための資料。
毎回の手順に必要なことは SKILL.md 側に書いてある。

## 1. DOM の構造

- スレッド = `ユーザー名 / 日時 / 本文 / 返信… / 返信を追加` のブロック。本文 (先頭の投稿) と各返信は
  どちらも `button[aria-label="コメントを編集する"]` と `button[aria-label="メニューを開く"]` を持ち、
  **見分ける属性は無い**。
- スクリプトは「`返信を追加` ボタンをちょうど 1 個含む最小の祖先」をスレッドブロックとみなし、
  その innerText の 3 行目 (`lines[2]`) を見出し (レンダリング後のテキスト) として使う。
  本文が空のスレッドは `(本文なし)` になる。
- 本文と返信の区別: marker を含む最小の祖先が「見出し行 (`heading + "\n"`)」を含めば本文、含まなければ返信。
  返信が複数あると「返信群の親」も候補に入るので、innerText が最短の候補を取る。
- エディタは `.cm-content` で、placeholder で用途が分かる: `内容を編集` (編集)、`返信内容を入力` (返信)、
  `スクラップにコメントを追加` (末尾の新規スレッド用。常に 1 個ある)。
- 送信ボタンの文言: 新規スレッド `投稿する` (ヘッダにも同名の別ボタンがあるので `className` に
  `Button-module` を含む方)、返信 `返信する`、編集 `更新する`、取り消し `キャンセル`。

## 2. CodeMirror は仮想化される

- 長い本文は画面外の行が DOM に無い (`.cm-gap`)。`innerText` で全文を検証しない。
- 差し替えは `Meta+A` → `keyboard.insertText(text)`。事前照合は `Meta+ArrowUp` で先頭へ戻して先頭 40 文字と
  `startsWith(expect)`、挿入後は先頭 20 文字の一致で見る。
- `locator.click()` は「安定待ち」でタイムアウトしがち (ユーザーが同じ Arc を操作していると特に)。
  クリックは `page.evaluate(() => btn.click())` の DOM クリックで行う。

## 3. Hidden comment

- ユーザーがメニューから「コメントを非表示にする」を選ぶと `Hidden comment` と表示され、本文も編集ボタンも
  DOM に無い。inspect の `threads` に出てこないスレッドは非表示。

## 4. 本文を上書きした事故

- 「返信を編集するつもりで、スレッド本文を上書きした」。原因は編集ボタンの特定ロジックが本文側を拾ったこと。
  対策として edit-comment.js は開いた直後に `__EXPECT__` (markdown 原文の先頭) を照合し、違えばキャンセルする。
- zenn に編集履歴は無い。上書きした本文はレンダリング済みテキストからしか復元できず、折りたたみの中身や
  markdown 装飾は失われる。

## 5. 削除対象を取り違えた事故

- 「CLI スレッドの返信を消すつもりが、末尾の独立スレッドを消した」。原因は「見出しを含まない祖先」という
  除外条件だけで候補を選び、別スレッドの同内容コメントが残ったこと。
- 対策: 候補の所属スレッドを見出しで**肯定条件**として要求し、dry run が返した `candidate` を本実行で再照合する
  (一致しなければ削除しない)。削除は `メニューを開く` → `削除` → モーダルの `削除する` の 2 段階。

## 6. ::: 記法

- `:::details タイトル` / `:::message` のタイトル行にバッククォートを入れると記号のまま表示される。
- 折りたたみの中身は閉じている間 `innerText` に出ない。検証は `summary` 要素のテキストで行う。

## 6b. 投稿後の検証 marker

- `add-thread.js` / `add-reply.js` は「先頭の非見出し行」を marker にして本文に含まれるか見るが、その行に
  インラインコード (バッククォート) があるとレンダリング後は記号が消えて一致せず `ok:false` になる。
  実例: 「`.gitconfig` を dotfiles から…」で始まる本文。投稿自体は成功している。
- 対処: `ok:false` かつ error 無しなら再投稿せず、リロード → `textContent` で見出しの有無と件数を確認する。
  本文の 1 行目をプレーンな文にしておくと偽陰性を避けられる。

## 6c. 本文の上限は 20,000 文字

- 超えると「コメントの本文には最大20000文字まで使用できます」が出て `更新する` / `投稿する` が効かず、
  エディタが開いたまま残る (スクリプトは `ok:false` + `editorsOpen` に `内容を編集` を返す)。
  実例: karabiner.json 全文 (27,081 文字) を折りたたみに入れようとした。
- 対処: 長い設定ファイルは GitHub のリンクにする。各スクリプトは実行前に `text.length > 20000` で止まる。
- 本文を書き換えた後にキャンセルすると confirm「変更が保存されていません。内容を破棄しますか？」が出る。
  ネイティブダイアログなので放置すると CDP が固まる。`cancel.js` と `edit-comment.js` の失敗パスは
  `page.once("dialog", d => d.accept())` で先に受諾している。手で操作したときは
  `browser_handle_dialog (accept: true)` で閉じる。

## 7. Arc / CDP

- `initializeServer: Timeout 30000ms` はスリープしたタブが `Runtime.evaluate` に無応答なのが原因。
  arc-browser スキルの手順で `/json/list` → 各タブに probe → HANG のタブを `/json/activate/<id>`。
- ユーザーが同じ Arc を操作しているので、Playwright の「現在のページ」はユーザーのタブ切り替えで変わる。
  各スクリプトは冒頭で `location.href` を `__URL_JSON__` と照合し、違えば `wrong page` で止まる。

## 8. 実行環境の制約

- `browser_run_code_unsafe` の `filename` はワークスペースルート相対。`<ワークスペース>/.playwright-mcp/` に置く。
  scratchpad やスキルディレクトリのパスは "outside allowed roots" で拒否される。
- スクリプト内で `require` は使えない (ReferenceError)。共通ロジックは各スクリプトに複製している。
- 値はすべて JSON リテラルで埋め込む。テンプレートリテラルに入れると `\`` と `${` のエスケープが要る。
